로컬 세션(`#11 20일선의 비밀 썸네일`)이 "GitHub 에 저장했다"고 했지만, 확인 결과:

- 계정의 저장소도 `boyjustin76/AC-Stock-` 하나뿐이다 (다른 곳에 갔을 수도 없다)

즉 **로컬의 썸네일 작업 기록은 로컬 PC 안에만 있다** (로컬 커밋이거나 미커밋).
지금 로컬 PC 는 꺼져 있어 세션도 접근 불가다. PC 를 켜면:

1. 로컬 클로드에게 시킬 것: `git log --oneline -5` · `git status` · `git branch` 결과 보고
2. **force push 금지를 명시할 것.** "썸네일은 너가 우선" 은 썸네일 파일 얘기다.
   그 사이 클라우드가 렌더 3.5배 가속(93s→26.8s)을 6커밋으로 올려 뒀다 —
   로컬이 자기 시점으로 강제 푸시하면 그게 날아간다.
3. 안전한 순서 (추천): 로컬 작업을 **별도 브랜치**로 먼저 푸시하게 한다
   (`git push -u origin HEAD:local/thumbnail-ch11`). 병합은 그 다음에 검토하고 한다.
4. 같은 브랜치에 바로 합쳐야 하면: `git pull --no-rebase` 후 —
   썸네일 파일 충돌은 로컬 것 채택, `log/build_worklog_db.py` 는 양쪽 항목을 합치고,
   `worklog.db`·`WORKLOG.md`·`worklog.html` 은 손으로 고치지 말고 **재생성**한다
   (`python3 log/save.py "..."` 가 셋 다 다시 만든다).

## 1. 요지 — 실행 속도는 문제가 아니다. 오독 위험이 문제다

썸네일 도구는 회차당 1회 도는 물건이라 런타임 병목이 없다 (지배 비용인 180MB
템플릿 열기/복제도 타이틀 캐시로 이미 상쇄). "효율화" 의 실질은 아래 정리다.

## 2. 발견 (중요한 순)

### ① 1세대 도구가 살아 있고, 지금 돌리면 "그때 그 틀린 썸네일"이 나온다
`tools/thumbnail.py` + `tools/psdwrite.py` 는 처음 시도(효과를 손으로 근사해 그리던
시절)의 짝이다. 서로만 참조하는 고립 계통인데 문제는 **지금도 멀쩡히 실행된다**는 것:

- 획·그림자를 코드로 근사해 그린다 → "효과가 회사 것과 다르다" 지적의 근원
- 종이배경을 **옛 11KB 다운샘플본**(`종이 배경.png`)으로, **불투명 100%**, (4,0) 에 얹는다
  — 실측값(원본 3.1MB · 30% · (4,−84))과 셋 다 다르다
- 틀을 템플릿 픽셀 대신 26px 핑크 사각형으로 다시 그리고, 로고도 다른 파일을 쓴다
- 출력은 포토샵이 두 번 거부한 psdwrite 경로다

**제안**: 두 파일 머리에 "레거시 — 실행 금지, 현행은 thumbnail_png.py" 경고를 달거나
`tools/legacy/` 로 옮긴다. (승인 주면 1분 거리. 로컬과 협의 대상.)

### ② `thumbnail_png.py` 의 타이틀 캐시가 입력을 안 본다
`titles()` 는 `title_{tag}.txt` 가 **존재하기만 하면** 재사용한다. 문구(VERSIONS)나
템플릿을 바꿔도 옛 타이틀이 조용히 나온다. 다음 회차에서 실제로 밟을 지뢰.
**제안**: 캐시 파일명에 (문구·폭·색) 해시를 넣거나, meta 에 spec 을 적고 비교.

### ③ 애셋 이중화 — `brand/thumbnail/` 에 신·구 세대 공존
| 구세대 (thumbnail.py 만 참조) | 현행 |
|---|---|
| `종이 배경.png` 11KB 다운샘플 | `종이배경.png` 3.1MB 원본 |

이름이 비슷해서 저장소만 보고 작업하는 쪽(로컬)이 헷갈리기 좋다. ①과 함께 정리.

### ④ 차11 이 소스에 박혀 있다
`VERSIONS` 문구·씬 이름·출력 파일명(`차명#11_...`)이 하드코딩이라 다음 회차마다
코드를 고쳐야 한다. **제안**: 회차 스펙을 JSON/CLI 인자로 분리. (썸네일 소유가
로컬로 갔으니 실행 여부는 로컬 몫 — 여기 적어 두는 것까지가 이쪽 역할.)

### ⑤ 잔가지
- `build_chart()`: probe 에 없는 태그를 **조용히** 건너뛴다 → 경고 한 줄 필요
- `titles()` 안 `find()`: 레이어 미발견 시 None 반환 → 바로 AttributeError. 명시적 에러로
- 폭 맞춤 로직이 두 벌이다: `thumbnail.py fit_size`(40~400) vs `psdedit._fit`(20~500).
  계열이 갈라져 있어 한쪽만 고치는 사고가 나기 쉽다 (① 정리 시 자연 해소)
- `psdedit._render()` 가 돌려주는 `left_pad` 는 아무도 안 쓴다

## 3. 잘 만들어져 있어 유지할 것

- **probe 컷 좌표 실측** — 차트에 없는 색(자홍·청록)을 찍어 읽는다. 짐작 제거의 정석
- **버튼·틀·로고·종이 = 템플릿 원본 픽셀** (`topil()` 추출) — "완전 똑같이" 의 유일한 답
- `psdedit.check()` — RunArray 짝·lyid 중복·그룹 여닫이를 저장 전에 잡는다
  (포토샵이 안 열리는 .psd 를 또 넘기는 사고의 재발 방지선)
- `bake_text()` 가 획·그림자를 안 그리는 것 — lfx2 가 살아 있어 두 겹 방지
- 종이 30% 산술 검증 (250.2 = 0.3×239.3 + 0.7×255) — 값이 실측에 묶여 있다
