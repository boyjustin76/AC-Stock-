# B → 총괄 · git_guard 본류 push 금지를 **이 저장소 범위**로 좁힘 · 2026-10-15

이정찬 지시로 포터블 공개 저장소를 따로 만들었다(`failloud`, github.com/boyjustin76/failloud).
거기서는 `main` 이 **그 저장소의 본류**라 push 를 막을 까닭이 없는데, 훅이 저장소를 안 가리고 걸려서
세션이 제 저장소에 푸시를 못 한다. 그래서 규칙 1 의 범위를 좁혔다. 병합 판단을 부탁한다.

## 무엇이 달라지나

| | 전 | 후 |
|---|---|---|
| `AC-Stock-` 에서 본류 push | 막음 | **그대로 막음** |
| 다른 저장소에서 `main` push | 막음 (오탐) | 통과 |
| 브랜치 이름 없는 push | 막음 | **어디서나 그대로 막음** |
| 판단 못 하는 경우 | — | **막는 쪽** |

**둘을 갈랐다.** '본류 금지' 는 우리 팀의 병합 정책이라 남의 저장소에 걸 이유가 없다.
'브랜치 이름을 적어라' 는 명령이 제 뜻을 드러내야 한다는 쪽이라 저장소를 안 가리고 둔다.

## 어떻게 가리나

훅은 **세션 작업 폴더**만 받는다. 그런데 명령은 `cd 다른저장소 && git push` 일 수 있어서,
명령 안의 `cd …` 와 `git -C …` 를 읽어 **대상 폴더**를 찾고 그 폴더의 `origin` 주소를 본다.
주소에 `AC-Stock-` 이 들어가면 건다. 못 읽으면(저장소가 아니거나 origin 이 없으면) **건다** —
판단 못 할 때 푸는 가드는 가드가 아니다.

이름을 더 보태려면 `AC_GUARD_REPOS="조각1 조각2"`. `PATH_HINTS` 의 `AC_GUARD_PATHS` 와 같은 꼴이다.

## 왜 `git config ac.role 총괄` 로 안 풀었나

그 길이 먼저 떠올라 `failloud` 안에 걸어 봤는데 **안 먹는다.** 훅이 `cwd`(세션 폴더 = `B_Image`)에서
설정을 읽기 때문이다. 명령 안에서 `cd` 해도 소용없다. 먹게 하려면 `B_Image` 에 걸어야 하는데
그러면 **차트명가 본류 가드가 통째로 풀린다.** 세 세션이 공유하는 안전장치라 그렇게 하지 않았다.
(그 설정은 시험 뒤 `--unset` 으로 걷어냈다.)

## 실측

```
cd .../failloud  && git push origin main --dry-run   → 통과 ("Everything up-to-date")
cd .../B_Image   && git push origin main --dry-run   → 막힘 (전과 같은 문구)
```

시험 `tests/test_git_guard.py` 25개 통과 (기존 19 + 새 6).
새로 넣은 것: 다른 저장소의 main 통과 · 여기 main 차단 유지 · 이름 없는 push 는 어디서나 차단 ·
`cd`/`git -C` 로 대상 찾기(공백 든 따옴표 경로 포함) · origin 못 읽으면 막음 · origin 주소로 가리기.
