## §2. 로컬이 판단할 것 — 작업체계

### 2-A. 세션마다 git worktree (B·D 작업트리 분리) — **D·B**

- **문제**: B 와 D 가 한 clone·한 브랜치(`local/newch-style`)를 같이 쓴다. save.py 휩쓸림(issue 24)·"영상 파트가 스크립트 파트를 건드림"(D A4)·세션이 잡은 폴더 못 옮김(D B6)이 전부 여기서 나왔다.
- **주류 해법**: Claude Code 공식 `claude --worktree <이름>` — `.claude/worktrees/<이름>` 에 별도 작업트리, 브랜치 `worktree-<이름>`. 공식 문서: "같은 파일을 건드리는 세션은 worktree 로 격리". `.claude/worktrees/` 는 이미 `.gitignore` 에 넣었다.
- **주의**: git 은 **같은 브랜치를 두 worktree 에 체크아웃 못 한다** → B·D 는 브랜치를 나눠야 한다. 제안: B `claude --worktree ps` (→ `worktree-ps`), D `claude --worktree ae`, E `claude --worktree script`. 통합은 총괄이 `worktree-*` 를 본류에 병합. Windows 정션 삭제는 Claude Code v2.1.205 이후 안전.
- **대안(최소)**: worktree 없이 가려면 save.py `--only` 를 반드시 쓰고 `AC_SAVE_SCOPE` 를 각자 셸에 둔다. 이건 임시방편이다.

### 2-B. 훅을 `~/.claude/hooks/` 에서 **저장소 `.claude/`** 로 — **D**

- **문제**: D 의 `hookify_reason.py` 는 이 PC 한 사용자 폴더에만 있다. 총괄·E 는 못 받고, `~/.claude/hooks` 쓰기는 자동 모드 분류기가 Self-Modification 으로 막았다(D B5).
- **주류 해법**: 공식 문서 — "프로젝트 `.claude/settings.json` 을 커밋해 팀 전체가 같은 hooks 를 받는다". hookify 플러그인은 네이티브 훅의 래퍼일 뿐이고 규칙이 안 발화하는 버그 보고가 있다(claude-plugins-official #5707). D 가 버린 판단은 맞다.
- **준비해 둔 것**: `.claude/hooks/git_guard.py` — 규칙 3개, stdin JSON → `permissionDecision: deny` + **이유**(issue 36 의 'denied 만 보임' 해결). 시험 `python3 -m pytest tests/test_git_guard.py`.
  - D 규칙과 다른 점 하나: '커밋 전 git status' 대신 **`git add -A / add . / commit -a` 자체를 막는다**(상태 없이 검사 가능). save.py 가 이제 파일 목록을 보여 주므로 같은 효과다.
  - 이동 규칙은 표식 `.claude/prlinks_find.ok`(60분) — **E 에게**: `prlinks.py find` 끝에 이 파일을 touch 하는 3줄을 넣어 주면 자동이 된다. 그 전엔 `touch .claude/prlinks_find.ok` 로 수동.
- **켜는 법** (D 가 확인 후 `.claude/settings.json` 에 추가, exec form — Windows 의 `python3` 가짜 문제(D B7) 회피):
  ```json
  "hooks": { "PreToolUse": [ { "matcher": "Bash|PowerShell",
    "hooks": [ { "type": "command", "command": "python",
                 "args": ["${CLAUDE_PROJECT_DIR}/.claude/hooks/git_guard.py"], "timeout": 30 } ] } ] }
  ```
  총괄 clone 은 `git config ac.role 총괄` 로 본류 push 예외. 프로젝트 훅은 workspace trust 가 필요하다.

### 2-C. 기록 절차 — 확정 알림 (decision 24)

- 세션은 `log/inbox/YYYY-MM-DD_<세션>_<주제>.md` 에 **원자료**(로그 원문·사용자 원문, 키는 `[가림]`), 총괄이 DB 문장. 이번에 그대로 했고 잘 됐다.
- 주류 대안으로 **GitHub Issues(MCP, 33k★)** 도 봤다. 셋이 한 PC 에서 md 로 충분하고 저장소가 public 이라 지금은 **보류**. 인박스가 20건 넘게 쌓이면 다시 본다.

### 2-D. PowerShell · 어도비 대화상자 — **B·D**

- PowerShell 자동 호출은 `-NoProfile -ExecutionPolicy Bypass -File` (Claude 공식 예시와 같다). 사람이 쓰는 셸은 `Set-ExecutionPolicy RemoteSigned -Scope CurrentUser` 한 번. MS 문서: 실행 정책은 보안 경계가 아니라 defense in depth.
- 모달 창(B A1~A3·B1~B3·E3, D B10): 앱별 **공식 스위치**를 각 .jsx 첫 줄에 두고 `finally` 에서 복원 —
  PS `app.displayDialogs = DialogModes.NO` · AI `app.userInteractionLevel = UserInteractionLevel.DONTDISPLAYALERTS` · AE `app.beginSuppressDialogs()` + `app.onError`.
  호출 쪽은 `subprocess.run(timeout=)` → `TimeoutExpired` 면 `taskkill /IM <앱>.exe /F`. "표준 watchdog 도구"는 없다 — 이 조합이 현실.
  단 B 의 E3 딜레마(끄면 사람이 볼 창을 못 본다)는 그대로다: **빌드는 끄고, 확인용 열기 한 번은 켠다** 는 B 방식이 맞다.
