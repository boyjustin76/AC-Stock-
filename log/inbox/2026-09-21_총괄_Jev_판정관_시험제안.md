## Jev 가 뭔가 (사실)
- **글을 만들지 않고 판단만 돌려주는 모델**("System One"). 넣는 것은 `state`(우리 자료) + 질문. 질문은 세 종류 — **Choice**(고르기: 선택·확률·confidence) · **Score**(단계 채점: score·확률·confidence) · **Noul**(참/거짓 0~1). 한 호출에 질문 여러 개를 병렬로.
- 값: 입력 토큰 100만 개당 $0.042, **출력 무료**. 맥락 64k. Python SDK `pip install typesafe-sdk`, 키 `TYPESAFE_API_KEY`, `POST https://api.typesafe.ai/v1/systemone`.
- 데이터: "사용자 데이터로 학습하지 않는다" 명시. 무보관(ZDR)은 기업 고객만. DPA·개인정보 링크 있음.
- **한국어 지원은 문서에 없다.** 실측 전엔 모른다.

## 약점 (문서 그대로, 우리 설계에 반영)
- 쓴 질문 그대로 읽는다 — 부정문·범위 말을 그대로. 질문을 짧고 문자 그대로 쓴다.
- 셈·날짜·수치 비교 못 한다 — 전부 코드로.
- state 에 무관한 내용이 많으면 정확도가 떨어진다 — 대본 전체 말고 **해당 대목만** 넣는다.
- 글 생성 아님 — 후보는 LLM 이 쓰고 Jev 는 고르기만.

## 시험 설계 (E, 반나절) — next_step 49
있는 자료로만 한다. 새로 만드는 표본 없음.
1. **한국어**: 합격 배너 8쌍을 state 로, Score 3단계("주제가 아랫줄에 있다" 등 팀장 기준 5개를 각각) — 답이 한국어 뜻을 읽는지. 못 읽으면 여기서 끝.
2. **순위**: S016 에서 **선배 확정본 vs E 1안(줄 뒤바뀐 것)** 을 같은 기준으로 채점 — 확정본이 위인가. 8회차 전부에서 **확정본 vs 1판 규칙으로 만든 문구** 를 비교, 확정본이 이기는 회차 수.
3. **방송본 5쌍**: 초안 vs 방송본을 "나간 것처럼 들리는가" 로 — 방송본이 위인가(E 가 만든 기준선 그대로).
4. confidence 분포를 같이 적는다. 높은데 틀리는 경우가 있으면 그게 제일 중요한 발견이다.
합격선(총괄 판단): 2 에서 **6/8 이상** + 1 에서 한국어 정상 → 판정관 단계로 채택(decision 35 갱신). 아니면 external_tool 14 를 rejected 로.
