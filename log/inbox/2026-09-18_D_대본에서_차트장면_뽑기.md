# D → 총괄 · 대본을 주면 차트 장면을 골라 찍는 것 · 2026-09-18

이정찬 목표: **대본을 주면 참고할 차트 장면을 쫙 찍어 주되, 고르는 기준이 팀장과 같을 것.**
팀장이 실제로 만든 차10(양방향 매매법) 자료를 뜯어 규칙을 뽑았다. 코드는 `tools/mt5/`.

> 대본 본문은 회사 자료라 여기 옮기지 않는다. 저장소는 public 이다.
> 규칙에 쓰는 낱말 조각(예: '지지선', '박스권')만 코드에 들어 있다.

## 1. 뜯어본 자료

`G:\…\차트명가(롱)\차명10_양방향 매매법` — 기획서+스크립트 docx · 소스 21개(png 14 · mp4 3) · 최종 프리미어 5벌.

## 2. 뽑아낸 팀장 기준

1. **비트 번호가 곧 파일 이름이다.** 대본 문장 앞의 `(4-1)` 이 `차10_4-1.png` 다. 12개 비트가 모두 대응된다.
2. **원리를 말하는 비트는 지표를 끈 민차트**를 쓴다. `2-2` 는 BTCUSD M5 민차트로 '상승 → 급락 → 반등'만 보여 준다.
   가격 움직임만으로 이야기가 읽혀야 하기 때문이다.
3. **본론에서 지표를 설명하는 비트는 대본이 말한 그 지표만** 켠다. `4-1`·`4-2` 는 20/200 EMA + ADX.
   (후킹 `1-3` 은 아무 차트여도 되니 당시 화면 그대로 — MA 하나 + 스토캐스틱이 켜져 있었다.)
4. 고르는 자리는 **대본 문장이 말한 사건이 실제로 일어난 구간**이다.
5. 형식: **MT5 창 캡처 1920×1032**(도구모음 포함). 프리미어에서 배율 **100%** 로 그대로 얹는다
   (프로젝트의 '비율 조정' 값 분포에서 100 이 359건으로 최다).
   화면에 보이는 봉은 **103~117개, 봉 간격 16px** 로 거의 일정하다 — 배율을 고정해 쓴다는 뜻이다.

## 4. 스스로 돌리며 잡은 것 (실측)

1. **`ChartScreenShot` 은 스크롤 자리를 무시하고 늘 최신 구간을 그린다.**
   지표 로그로 확인했다 — `첫보임=2080 보이는봉=117` 인 상태에서 찍었는데 그림은 최신이었다.
   요청 크기가 차트 창보다 크면 더 심하다(봉이 커지는 게 아니라 더 많이 들어온다).
2. **`ChartNavigate` 로 화면을 옮기는 것은 된다** (`첫보임 115→900`, nav=1). 단 조건이 있다:
   자동스크롤을 끄고, 그 날짜 이력을 `CopyRates` 로 먼저 불러야 한다.
3. **`chart_apply_template` 은 지표를 통째로 갈아 끼운다.** 바로 이어서 지표를 붙이면 같이 지워진다 — 3초 쉰다.
4. 터미널은 **쓸 수 있는 지표 목록을 시작할 때 한 번** 만든다. 새로 컴파일한 지표는 **재시작해야** 잡힌다(한 번만).
5. 그래서 최종 조합은 **지표로 옮기고 → 창을 PrintWindow 로 찍고 → 되돌리기** 다. 팀장 그림도 어차피 창 캡처다.

## 5. 남은 것

- 12장 **일괄 촬영**: 지금은 열린 차트 하나 기준이다. 비트마다 심볼·주기를 바꿔 가며 도는 부분이 남았다.
- **콘티 이미지**와 **AE 컴포지션** 생성.
- 규칙 표(§2-2·2-3)는 차10 한 편에서 뽑은 것이다. **다른 회차로 검증**하면 더 단단해진다.
- 판단이 필요한 것: 찍은 그림을 **회사 드라이브 소스 폴더에 바로 넣을지**, 우리 폴더에 모았다가 사람이 옮길지.
  지금은 회사 드라이브에 아무것도 쓰지 않는다.
