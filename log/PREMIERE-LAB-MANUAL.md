# 프리미어 직접 편집 실험 매뉴얼 — D 세션용

> 작성: 클라우드 저장소 관리 세션 (2026-08-28). 근거는 두 개다 —
> 이 저장소의 실측 기록(`log/worklog.db`)과, 같은 PC 에서 포토샵 자동화를
> 성공시킨 로컬 세션의 실험 기록 전문(2026-08-28 수신). 추측으로 쓴 항목은 없다.

## 무엇을 하는 실험인가

파이프라인 2단계(영상 편집)를 자동화한다. 목표 형태는 포토샵에서 성공한 것과 같다:

> **시퀀스를 통째로 복제해서 그 안의 소스만 교체한다.** 키프레임·모션 효과는
> 프리셋 것을 그대로 물려받아, 사람이 프리미어에서 직접 열어 고칠 수 있게 남긴다.

산출물이 mp4 가 아니라 **편집 가능한 .prproj** 라는 점이 지금 클립 생성 방식과 다르다.
이건 **실험이고 실패할 수 있다.** 클립 생성 방식(`src/render/`)은 검증된 납품 경로로
그대로 두고, 성공하면 렌더러가 뽑은 차트 클립이 이 경로의 "교체할 소스"가 된다.
두 방식은 경쟁이 아니라 합성이다.

역할 분담: **D(너, 로컬) = 실험실. 클라우드 = 저장소 관리와 판정.**
.prproj 는 gzip 압축 XML 이라 프리미어 없이도 읽힌다 — 네가 만든 파일을 저장소에
올리면 클라우드가 gunzip 으로 열어 시퀀스·키프레임이 의도대로 박혔는지 판정한다.
포토샵 때 로컬·클라우드가 서로 검증한 구도이고, 그때보다 조건이 좋다.

## 0. 시작 전 확인 (이걸 건너뛰고 시작하지 마라)

1. **PC** — 포토샵 실험이 성공한 사무실 PC 인가? 회사 드라이브가
   `D:\01_구글 드라이브(파가드AC)\트레이딩팩토리\` 에 마운트돼 있어야
   프리셋의 미디어 참조가 살아 있다 (`prproj_fact` 4번에서 실측한 경로다).
2. **프리미어 버전** — 도움말 > 정보 에서 확인해 기록해라. 2023+ 여야 하고,
   버전에 따라 스크립팅 계층(ExtendScript/CEP vs UXP)이 다르다.
3. **git 상태** — 작업 시작 전에 반드시:
   ```
   git fetch origin
   git log --oneline -3 origin/claude/futures-youtube-video-edit-fhio4s
   ```
   그리고 **네가 만질 파일을 다른 세션이 만졌는지 diff 로 먼저 봐라.**
   푸시할 때 알면 늦다 — 이 저장소에서 실제로 두 번 겹쳤고, 세 번째는
   시작 전 fetch 로 막았다.

## 2. 사용자(이정찬)에게 직접 시킬 것

에이전트가 못 하거나 하면 안 되는 것들이다. **명령을 줄 때는 PowerShell 5.1 기준으로 줘라** (§6).

1. **git 로그인 (한 번)** — 비대화형 셸에서는 브라우저 로그인이 안 열려서 푸시가 막힌다
   (로컬 세션이 실제로 막혔다). 사용자가 자기 터미널에서:
   ```
   git ls-remote https://github.com/boyjustin76/AC-Stock-.git
   ```
   브라우저 인증 창이 뜨면 로그인. 이후 자격증명 캐시로 에이전트 푸시가 통과한다.
   **토큰·비밀번호를 에이전트가 받지 마라. 자격증명은 사용자만 다룬다.**
2. **작업 폴더와 프리셋 사본 만들기** —
   ```
   mkdir C:\pprolab
   Copy-Item "<저장소>\brand\premiere\차트명가_메인프리셋(24버전).prproj" C:\pprolab\src.prproj
   ```
   실험은 `C:\pprolab\src.prproj` 사본으로만 한다. **회사 드라이브의 원본을 열지 마라.**
3. **프리미어 실행 확인** — M1 첫 시도 때 프리미어가 대화상자를 띄우면 사람이 닫아야
   할 수 있다. 첫 실행은 사용자가 화면을 보는 상태에서 한다.
4. **(M4 이후, MCP 로 갈 때만)** Claude Desktop 설치, 미서명 확장 허용 등 —
   M1~M3 에서는 아무것도 설치하지 않는다. MCP 를 붙이게 되면 설치 전에
   클라우드 세션에 코드 보안 검토를 먼저 요청해라.

## 3. 대원칙 — 포토샵에서 피 흘리고 배운 것

전부 같은 PC, 같은 회사 템플릿에서 실제로 겪은 일이다. 요약이 아니라 규칙으로 지켜라.

1. **읽기는 자유, 쓰기는 앱을 통해서.** gunzip 으로 .prproj 를 읽는 건 마음껏 해라.
   그러나 **XML 을 고쳐 다시 gzip 하는 실험은 금지다.** psd-tools 로 쓴 .psd 는
   원인 셋을 고치고도 포토샵이 거부했고, 앱(COM)을 조종하니 한 번에 됐다.
2. **MCP 말고 COM+ExtendScript 부터.** 포토샵 드라이버의 전부는 이거였다:
   ```powershell
   $ps = New-Object -ComObject Photoshop.Application
   $ps.DisplayDialogs = 3          # 대화상자 끄기. 안 하면 멈춰 선다
   $result = $ps.DoJavaScriptFile($jsx)
   ```
   프리미어도 COM 계열(`Premiere.Application` 류)을 노출한다. 이 경로는 설치할 게
   없고(미서명 확장·Claude Desktop·커넥터 불필요), 보안 검토도 필요 없다.
   실패하면 그때 MCP 2종(`external_tool` 에 조사돼 있다)으로 간다.
3. **공개 API 에서 막혔다고 "프리미어가 못 한다"고 결론 내지 마라.** 포토샵 DOM 에는
   레이어 효과도 문자 서식도 없지만 한 층 아래(ActionManager)에 다 있었다.
   프리미어의 그 층은 `app.enableQE()` 로 여는 `qe` 다 — 문서가 없고 버전마다
   바뀌지만, 공개 DOM 이 못 하는 일을 한다. UXP 로 넘어간 버전이면 계층이 또 다르다.
4. **쓴 값이 오류 없이 되돌아가면 "이미 계산된 짝"을 찾아라.** 포토샵에서 size 를
   써도 조용히 무시된 원인은 impliedFontSize(파생값)가 이기는 구조였다.
   프리미어는 이런 쌍이 훨씬 많다 — 클립의 start/end/inPoint/outPoint/duration
   (서로 계산 가능), 파라미터의 현재 값 vs 키프레임 값(키프레임이 하나라도 있으면
   현재 값은 표시용), 프레임레이트 틱 vs 타임베이스, 스케일 vs 소스 해상도
   (소스를 교체하면 재계산될 수 있다).
5. **화면으로 확인하지 마라. 파일을 다시 읽어라.** 만드는 스크립트와 **검사하는
   스크립트를 처음부터 따로** 만들어라. 저장 → 다시 열어(또는 gunzip 해서) 숫자를
   읽어 확인한다. "색은 들어가고 크기는 무시된" 것을 잡아낸 방법이다.
6. **대표값 하나를 주는 API 를 믿지 마라.** `textItem.color` 는 첫 글자 색만 주면서
   오류를 안 냈다. 키프레임 걸린 파라미터의 단일 value, 여러 클립이 걸친 트랙의
   대표 속성, 중첩 시퀀스의 겉보기 길이 — 여러 개일 수 있는 것은 전부 목록으로 읽어라.
7. **하나만 보고 따라 하면 카피캣이 된다.** 모션 프리셋 하나를 재현하지 말고
   `motion_preset` 전부와 회차 .prproj 여러 개를 훑어 공통 구조를 먼저 뽑아라.
   그리고 기존 문서를 의심해라 — 실측이 이긴다 (문서의 "폭 맞춤" 규칙이 실측으로
   뒤집힌 전례가 있다).
8. **잠금부터 풀어라.** 포토샵에서 잠긴 레이어 때문에 원인 불명 오류(8800)로 두 번
   헤맸다. 잠긴 트랙·잠긴 클립·오프라인 미디어·읽기 전용 상태를 **작업 전에 전부
   푸는 함수를 먼저 만들어라.**
9. **정리도 작업의 일부다.** 회차 시퀀스 하나만 남기고 나머지 시퀀스·빈·미사용
   애셋을 지운 뒤 저장해라. 포토샵에서 195MB → 11.5MB 가 됐다. 미사용 참조는
   검증도 어지럽힌다.
10. **위치는 하드코딩하지 말고 특징으로 찾아라.** 트랙 번호를 박지 말고 클립
    이름·길이·시작점 같은 성질로 찾는다 (포토샵에서는 "종이 배경은 항상 (4,-84)"
    라는 성질을 썼다).

## 4. 마일스톤 — 한 번에 가지 말고 한 칸씩

각 단계의 완료 조건은 같다: **저장된 .prproj 를 다시 읽어(되읽기 검사기 또는 gunzip)
숫자로 확인하고, 옆가지에 올려 클라우드 판정을 받는다.** 실패해도 어느 칸에서
막혔는지가 기록으로 남는다.

- **M1. 열기·복제·저장** — COM 으로 프리미어를 띄워 `C:\pprolab\src.prproj` 를 열고,
  시퀀스 하나를 복제하고, 다른 이름으로 저장한다. 검증: 저장본을 gunzip 해서
  시퀀스 수가 하나 늘었는지, FrameRate 틱이 8475667200 그대로인지.
- **M2. 소스 교체** — 복제한 시퀀스 안의 클립 하나를 렌더러가 뽑은 차트 png/mp4 로
  교체한다 (`npm run render` 산출물을 `C:\pprolab` 로 복사해 두고 절대경로 참조).
  검증: `<ActualMediaFilePath>` 가 새 파일을 가리키는지, 교체한 클립의 스케일이
  멋대로 재계산되지 않았는지 (§3-4).
- **M3. 키프레임** — 교체한 클립의 모션 파라미터에 키프레임을 읽고 → 하나 수정하고
  → 새로 만들어 본다. `motion_preset` 의 프레임 수·이징을 재현하는 게 목표.
  검증: `<Keyframes>` 평문을 파싱해 틱·값·보간타입이 의도와 일치하는지.
  **여기가 제일 막히기 쉬운 칸이다** — 공개 API 로 안 되면 qe 층을 보고(§3-3),
  그래도 안 되면 그 사실 자체가 수확이니 기록하고 멈춰라.
- **M4. 회차 조립** — 대본 타임코드에 맞춰 컷 여러 개를 배치한 시퀀스를 만들고,
  다른 시퀀스·미사용 애셋을 정리해 저장(§3-9). 검증: 클라우드가 컷 경계 틱을
  대본 타임코드와 대조.

## 6. 윈도우 함정 — 그대로 밟게 되는 것들

- PowerShell 5.1 에 `&&` 가 없다. `A; if ($?) { B }` 로.
- `.ps1` 은 **UTF-8 with BOM** 으로 저장. BOM 없으면 한글 주석이 cp949 로 깨져
  파서가 죽는다 ("Unexpected token '}'") — 원인이 주석에 있어 코드만 봐서는 못 찾는다.
- 파이썬 subprocess 는 `encoding="utf-8"` 명시 + `PYTHONUTF8=1`.
  `text=True` 만 쓰면 cp949 디코딩으로 터진다.
- JSX/ExtendScript 문자열의 경로는 전부 슬래시(`/`). 역슬래시는 이스케이프로 먹힌다.
  스크립트는 heredoc 으로 흘리지 말고 파일로 써라.
- ExtendScript 에 JSON 이 없는 판이 있다 — config 는 `f.encoding = "UTF-8"` 후
  `eval("(" + txt + ")")` 로 파싱 (포토샵 쪽 `build_thumb.jsx` 참조).
- COM 첫 줄에 대화상자 끄기 설정을 찾아 걸어라. 포토샵의 `DisplayDialogs = 3` 에
  해당하는 것이 없으면, 첫 실행은 사용자가 지켜보게 해라 (§2-3).
