## §6 에 추가할 함정

1. **BridgeTalk 본문에 스크립트 소스를 실어 보내지 마라.** 역슬래시 이스케이프가
   전송 중에 한 번 더 이스케이프된다. `"\t"` 가 프리미어에서 **글자 `\t`** 로 실행됐다.
   본문은 `$.evalFile(new File("<경로>"))` 한 줄만 보내고, 소스는 프리미어가 디스크에서
   직접 읽게 한다. 덤으로 본문이 짧아져 메시지 크기 제한에서도 자유롭다.
2. **`_job.txt` 같은 인자 파일은 BOM 없는 UTF-8 로 써라.** 저장소 경로에 한글이 있어
   ASCII 로는 안 되고, PowerShell 5.1 의 `Set-Content -Encoding UTF8` 은 BOM 을 붙여
   JSX 가 경로를 못 찾는다.
   `[System.IO.File]::WriteAllText(p, s, (New-Object System.Text.UTF8Encoding($false)))`.
3. **`app.openDocument` 는 비동기다.** 호출 직후 `numSequences` 가 0 일 수 있다.
   `$.sleep` 으로 폴링해라 (이 PC 에서는 대부분 0초 만에 들어왔지만 보장은 없다).
4. **`app.enableQE()` 는 두 번째부터 `false` 를 준다.** 실패가 아니라 "이미 켜져 있다"다.
   반환값으로 성공을 판정하지 말고 `typeof qe` 를 봐라.
5. **네이티브 함수의 `.length`(arity)는 전부 0 이다.** `app.openDocument.length` = 0.
   인자 개수를 알아내는 데 못 쓴다.
6. `run.ps1` 은 UTF-8 **with BOM**, JSX 는 BOM 없는 UTF-8. 섞으면 각각 다르게 깨진다.

### ⚠ 정정 — `m1_after_open_only.prproj` 은 기준선으로 쓰면 안 된다

motion_preset #1 밑줄/강조바 그리기 (변형/높이 비율 조정 2키, 3곳)
   간격 33,902,668,800      =  4.0000 프레임@29.97   /  4.0040 프레임@30.0

29.97 쪽만 정수다. **M1 에서 미뤄 둔 "29.97 이냐 30.0 이냐" 질문의 답이다 — 모션은 29.97.**
다만 **한 파일 안에 두 격자가 섞여 있다**: 그래픽/텍스트의 불리언 키프레임은
30.0 격자다 (Δ가 7.0000f@30.0 · 3.0000f@30.0 로 떨어진다). 파라미터 종류마다 다르니
격자를 하나로 가정하면 안 된다.

### 보간 상수 매핑 — 실험으로 확정

`getInterpolationTypeAtKey` 가 없으니 API 상수와 파일 코드의 대응을 모른다.
chartA 클립의 스칼라 파라미터에 키 8개를 1프레임 간격으로 만들고 0~7 을 하나씩 걸어
저장한 뒤 파일을 읽었다 (`jobs/m3_interp.jsx`):

```

```

이름은 확인된 것만 단다 — **0 = 선형, 5 = 이즈.** 근거가 둘이다:
`prproj_fact` 14, 그리고 **회사 프리셋 실물** — `motion_preset` #1 이 세 군데에서
`1.(interp=0) → 100.(interp=5)`, #3 이 `5,5,5,5`(이즈 4단). 나머지 1·2·3·4·6·7 은
코드가 그대로 들어간다는 것만 확인했고 이름은 미확인으로 둔다.

**`Time` 객체에 `.ticks` 문자열을 넣는 경로는 오차가 없다.** 8키 전부 의도한 틱에
정확히 안착했다. 초(number)로 환산하면 3600초대에서 반올림이 격자를 흔들 수 있으니 쓰지 마라.

## 2026-08-28 · M4-a/b — 정리(§3-9) 통과, 컷 배치는 미착수

M4 는 둘로 나뉜다. **정리(§3-9)는 컷 배치와 무관해서 먼저 했고 통과했다.**

### 삭제 API — 이름을 믿으면 안 된다

| | |
|---|---|
| **`sequence.close()`** | **아무것도 안 지운다.** 타임라인 탭만 닫는다. 9개에 걸었는데 10 → 10 그대로였고 **오류도 안 났다** |
| `sequence.delete` · `remove` · `deleteSequence` | 전부 `undefined` |
| **`app.project.deleteSequence(seq)`** | 이게 진짜다 |
| `projectItem.delete` · `remove` | 전부 `undefined` — 미디어 항목을 직접 지우는 함수가 **없다** |
| `projectItem.createBin` · `moveBin` · `deleteBin` | 있다. **미사용 항목을 빈 하나로 몰아넣고 빈째로 지운다** |

`close()` 는 §3-4 가 말한 "쓴 값이 오류 없이 되돌아가는" 유형의 정반대 사례다 —
**호출이 성공하고 아무 일도 안 일어난다.** 개수를 세서 확인하지 않았으면 못 잡았다.

### ⚠ 함정 — "남길 것 하나 빼고 다 지운다" 로 하면 남긴 것이 부서진다

1차 시도에서 그렇게 했더니 남긴 시퀀스의 클립이 **44 → 41** 로 줄었다.
`롱폼 고정 양식 복사` 가 타임라인에서 **중첩 시퀀스 10 · 08 · 11 을 쓰고 있었다.**
그것들을 지우니 그 클립들이 같이 사라진 것이다. 오류는 안 났다.

고친 방법 — **의존 관계를 재귀로 먼저 계산한다:**

1. 모든 시퀀스의 `sequence.projectItem.nodeId` 로 `nodeId → 시퀀스 이름` 지도를 만든다.
2. 남길 시퀀스에서 출발해 비디오·오디오 트랙의 모든 클립을 훑고,
   클립의 `projectItem.nodeId` 가 지도에 있으면 그 시퀀스도 남길 목록에 넣는다 (재귀).
3. 남길 목록에 없는 것만 `deleteSequence`.

결과: 남길 목록 4개(`롱폼 고정 양식 복사` + 중첩 10·08·11), 지운 것 5개.
**중첩 시퀀스 08 이 두 개 있는데 쓰이는 쪽만 남았다** — 이름으로 골랐으면 틀렸을 자리다.

미사용 애셋도 같은 방식으로 골랐다 — 남은 시퀀스 전부가 쓰는 `nodeId` 를 모으고,
나머지 40개를 `_지울것` 빈으로 옮겨 빈째로 삭제. 지운 목록에 `차10_1-5.png` 가 들어 있다
(M2 에서 chartA 로 교체했고, 그걸 쓰던 원본 시퀀스도 지워졌으니 맞다).

### ⚠ 함정 — 프리미어는 프로젝트를 계속 열어 둔다

세션 내내 잡을 돌리다 보니 **프로젝트가 9개 열린 채**였다. 여기서 두 가지가 물렸다:

1. **디스크의 파일을 새로 복사해 덮어써도 이미 열린 프로젝트는 안 바뀐다.**
   `m4_src.prproj` 를 깨끗한 사본으로 덮어썼는데, 프리미어는 직전 실행의 **손상된
   메모리 상태**(1 시퀀스·41 클립)를 그대로 보여 줬다. 그 상태로 판정할 뻔했다.
2. **저장 대상이 열려 있으면 `saveAs` 가 예외 없이 `false` 를 돌려준다.**
   반환값을 안 봤으면 "저장됐다" 고 착각했을 것이다.

그래서 잡 첫머리에서 **열린 프로젝트를 전부 닫고 새로 연다:**

```javascript
for (var g = 0; g < 50 && app.projects.numProjects > 0; g++)
    app.projects[app.projects.numProjects - 1].closeDocument(0, 0);   // 저장 안 함, 안 물어봄
app.openDocument(SRC, 1, 1, 1, 1);
```

"이미 열려 있으면 재사용" 은 빠르지만 **재현성이 없다.** 쓰지 마라.
