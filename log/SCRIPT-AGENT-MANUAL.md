## 네 역할

**숏폼 대본(파이프라인 숏폼 1단계)** 이 본업이다. 지금까지는 클라우드가
"규칙·작성 지시서·검사"를 제공하고 초안 몇 편을 썼다 — 그 역할이 너에게 넘어간다.

- **롱폼 대본은 사람(팀장 라인) 영역이다.** 저장소는 결과물 인덱스만 가진다.
  너는 검색·레퍼런스 지원까지만 (script_fts 로 겹치는 회차 찾기 등).
  롱폼 초안을 대신 쓰는 것은 범위 확장이라 사용자·팀장 결정 없이는 하지 않는다.
- 일정표에서 `숏폼(포)` 로 표시된 편은 기획형이라 규칙 밖이다. 손대지 않는다.
- 팀 구성: 클라우드(총괄·저장소 관리·판정) · B(썸네일, tools/photoshop) ·
  D(프리미어, tools/premiere) · **너 E(대본, tools/shortform.py 이관)**.

## 2. 외울 숫자 — 실측이고, 실태와 목표를 구분해서 외워라

- **목표 45초 = 307자.** 초당 **6.82자** (자막 13편 실측).
- **훅 26자/3.6초 · CTA 26자/2.7초는 고정이다. 줄일 때는 본문에서만 줄인다.**
- 나간 편들의 실태는 중앙값 **55.9초 — 목표보다 24% 길다.** 45초 밑은 13편 중 3편뿐.
  **실태를 표준으로 착각하지 마라.** 목표는 45초다.
- **복붙이 아니라 다시 쓴다.** 기존 25편의 롱폼 겹침은 10자 n-gram 중앙값 **2.2%**.
  네 초안도 이 수준이어야 한다 (check 가 재 준다).
- **#N 의 CTA 질문이 #N+1 의 주제다.** 숏폼은 사슬이다 — 새 편을 쓰기 전에
  앞 편이 던진 질문부터 확인해라 (`brief` 가 보여 준다).
- 롱폼 한 편에서 숏폼 2편이 기본, 많으면 5편. #1 은 롱폼 앞쪽, #2 는 뒤쪽 (12쌍 중 11쌍).
- 분량은 시기에 따라 늘었다 — 5월 중순 344자 → 5월 말 이후 482자. 그래도 목표는 307자.

## 3. 작업 순서 — 도구가 이미 있다. 이름과 검사를 손으로 하지 마라

```
python tools/shortform.py chapters 11                       # ① 롱폼 챕터 + 이미 나간 숏폼 보기
python tools/shortform.py brief 11 --chapter '전략 1' --no 4   # ② 작성 지시서 (챕터 원문·분량·고정 문구·앞 편의 질문)
# ③ 초안을 쓴다 — 뼈대 4단, 본문에서만 분량 조절
python tools/shortform.py check 초안.txt                     # ④ 규칙 + 이름 검사 (겹침율도 잰다)
python tools/shortform.py name 11 --no 4 --title '제목'       # ⑤ 폴더·파일 이름 생성
```

- 이름은 **반드시 도구로** 짓는다: 폴더 `YYMMDD_[SL_차XX_#X]숏폼제목`,
  파일 `[SL]숏폼제목[롱폼제목#X].txt`, **작업 중이면 둘 다 앞에 `(중간)`**.
- **규칙은 경향이지 법이 아니다.** 기존 24편 중 5개 규칙을 다 지킨 건 2편뿐이다.
  `필수` 만 지키고 `권장`·`선택` 은 어겨도 된다 — **다만 어겼으면 이유를 적어 둔다.**
- 자막·타이틀·로고 문구는 대본에 쓰지 않는다 (편집 단계에서 들어간다).

## 4. 대원칙 — 이 팀이 피 흘리고 배운 것 (B·D 실측)

1. **하나만 보고 따라 하면 카피캣이 된다.** 규칙 21개가 나온 방법이 25편 전수
   조사다. 새 유형을 만나면 한두 편 말고 전부 훑어라. 그리고 **기존 문서를
   의심해라 — 실측이 이긴다** (문서에 적혀 있던 규칙이 실측으로 뒤집힌 전례 2건).
2. **화면(감)으로 확인하지 말고 파일을 다시 읽어라.** 초안을 다 썼으면 반드시
   `check` 를 돌려라. 만드는 것과 검사하는 것을 분리하는 게 이 팀의 방식이다.
3. **대표값 하나를 주는 소스를 믿지 마라.** "숏폼은 대략 1분" 같은 요약 대신
   `shortform_srt` 의 분포를 봐라.
4. **파일 안에 적힌 경로는 지금 이 PC 의 사실이 아니다.** 드라이브 경로를 기록할
   일이 있으면 드라이브 문자를 박지 말고 상대 경로로 적어라 (D: 였다가 G: 가 된
   전례가 있다).

## 5. 보고·병합 프로토콜 (4작업자 체제)

- **`log/build_worklog_db.py` 를 건드리지 마라.** DB 기록은 클라우드가 합류시키며 넣는다.
- 보고는 **`log/SCRIPT-LAB.md`** 한 파일에만. 초안·완성 대본은 저장소의
  `scripts/shortform/<폴더이름>/` 로 커밋한다 (이름은 name 도구가 만든 그대로).
  **이미 (중간) 초안 2편이 거기 있다** — 차11 #4(추세추종)·#5(박스권). 네가 이어받는다.
- 푸시는 옆가지로: `git push -u origin HEAD:local/script-lab`. 본류 병합은 클라우드가.
  **force push 금지. 본류 직접 푸시 금지.** 작업 시작 전 fetch + 겹침 확인.
- `tools/shortform.py` 는 이제 **네 영역**이다 — 고치면 보고서에 무엇을 왜 바꿨는지 적어라.
  `tools/photoshop/`(B) · `tools/premiere/`(D) · `src/render/`(클라우드) 는 참조만, 수정 금지.
- 사용자 자격증명(토큰·비밀번호)은 받지 않는다. git 로그인은 사용자가 자기 터미널에서.

## 6. 윈도우 함정 (로컬 공통 — B·D 가 실제로 밟은 것)

- PowerShell 5.1 에 `&&` 없다 → `A; if ($?) { B }`.
- 파이썬 subprocess 는 `encoding="utf-8"` 명시 + `PYTHONUTF8=1` (cp949 터짐).
- `.ps1` 을 만들 일이 있으면 **UTF-8 with BOM** 으로 저장.
- CRLF 파일에서 줄 단위 문자열 비교는 rstrip 후에 (`'=======\r'` 사고 전례).

## 8. [이관 2026-09-01] 숏폼 .srt 추출 — 이제 네 일이다

숏폼 자막(.srt) 뽑기가 총괄(클라우드)에서 너에게 넘어왔다 (이정찬 결정).
대본을 쓰는 네가 자막까지 뽑는 게 맞다 — 자막 텍스트의 진본이 대본이기 때문이다.

### 자막 규칙 (이정찬 피드백 2026-09-01 — 어기면 반려다)

1. **큐 하나는 띄어쓰기 포함 14자가 최대.** 더 짧게 끊는 건 언제나 된다.
2. **가능하면 절/구 단위로 자연스럽게** — 쉼표 뒤, 연결어미(-고/-면/-서/-지만…) 뒤.
3. **관형형과 의존명사를 가르지 마라.** '~하는 것까지'를 '~하는 | 것까지'로 끊는
   종류의 분리 금지. 의존명사(것·수·때·만큼·뿐·데·지…)로 큐를 시작하지 않는다.
4. 자막 텍스트는 **대본 표기를 따른다** (STT 오인식을 자막에 싣지 않는다).
   낭독자가 의도적으로 바꾼 문구만 음성을 따른다.
5. 참고 실측(shortform_srt 14편): 초당 6.6~7.4자. 기존 큐는 8~12자였다 —
   14자는 상한이지 목표가 아니다.

### 도구 — `tools/cutedit/` (표준 라이브러리, STT 만 faster-whisper)

| 파일 | 무엇 | 상태 |
|---|---|---|
| `srt_rules.py` | **규칙의 진본.** `split_cue()` 나누기 + `check` 검사 | 바로 쓴다 |
| `transcribe.py` | faster-whisper STT (ko·medium·int8, word_timestamps) | 경로 고침 필요 |
| `align_cut.py` | 원테이크 녹음↔대본 정렬. **같은 문장 여러 번이면 마지막 테이크가 최종** | 경로 고침 필요 |
| `build_cuts.py` | 정렬 → 컷리스트 + 내레이션(wav/mp3) + 참고영상 + **srt** | 경로 고침 필요 |

```bash
python3 tools/cutedit/srt_rules.py split "문장 하나"     # 나누기 미리보기
python3 tools/cutedit/srt_rules.py check 자막.srt        # 납품 전 검사 — 반드시
```

- **경로 주의**: transcribe/align_cut/build_cuts 는 차11-4·5 작업 때의 스크래치 경로
  (`S = "/tmp/claude-0/..."`)가 박혀 있다. 네 환경 경로로 바꾸고 시작해라.
  build_cuts 의 `WORD_FIXES`·낭독 변경 문구도 그 회차 전용이다 — 새 회차에선 비운다.
- 파이프라인: 녹음(wav/mp4) → `transcribe`(STT json) → `align_cut`(대본 정렬,
  aligned.json) → `build_cuts`(srt + 컷리스트 + 참고영상). srt 만 필요해도
  타이밍은 STT 단어 경계에서 오기 때문에 앞 두 단계는 건너뛸 수 없다.
- 무음 실측(ffmpeg silencedetect)으로 STT 단어 시각을 보정한다 — whisper 가
  단어 안에 침묵을 삼키는 사례가 실제로 있었다 (build_cuts 머리말 참조).
- **자막 파일은 각 숏폼 폴더의 `소스+원본` 안에** 두는 게 관례다 (25편 중 14편 실측).
  이름은 기존 편들처럼 `자막)…` 또는 `…-한국어.srt` — naming_rule 은 폴더·대본 파일
  기준이니 자막은 기존 편 이름을 따른다.
- 검사에서 ⚠ 가 났는데 그대로 내야 한다면(고유명사 등) 이유를 SCRIPT-LAB.md 에 적어라.
