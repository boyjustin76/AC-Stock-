# tools/theone — 더원트레이더 시리즈 전용

**이 폴더는 차트명가가 아니다.** 저장소의 나머지(`tools/shortform.py`,
`log/SCRIPT-LAB.md`, `brand/`)는 전부 **차트명가** 기준이다. 규칙·수치를 서로
옮겨 쓰지 말 것.

| | 차트명가 (숏폼) | 더원트레이더 (숏폼) |
|---|---|---|
| 회차 이름 | `YYMMDD_[SL_차XX_#N]제목` | `SNNN_제목_YYMMDD` |
| 자료 위치 | `03_영상_소스_숏츠/차트명가(숏)` | `더원트레이더_JG/숏폼_프로젝트모음` |
| 대본 뼈대 | 훅·본문·CTA | `제목` + `①훅 ②근거 ③본론 ④결론` |
| 초당 글자수 | 6.72~6.91자 | **5.43~5.91자** |
| 규칙 문서 | `log/SCRIPT-LAB.md` | 이 README + `숏폼_프로젝트모음/상단배너_공식.md` |

## 일하는 방식 — 눈대중 금지

**규칙은 정답 자료에 대고 채점해서 고른다** (이정찬 지시, 2026-09-09).

1. 정답 자료를 먼저 찾는다 — 사람이 손으로 고친 수정본, 최종본 영상, 확정 문구.
   없으면 규칙을 세우지 말고 없다고 말한다.
2. 채점대를 짠다. 후보를 넣으면 정답과 얼마나 맞는지 숫자가 나오게.
3. 후보를 하나씩 넣어 기여도를 잰다. **나빠지는 것은 그럴듯해도 버린다.**
4. 미리 답을 정해 놓고 채점시키지 않는다. 공간 전체를 훑어야 안 보이던 답이 나온다.
5. **표본 수를 같이 말한다.** 얇으면 얇다고 한다.

이 방식으로 뒤집힌 것 — 배너 규칙(1판 `아랫줄=최다 출현어` → 2판 `제목을 쪼개
뒤집기`), 자막 검사(납품본을 반려하던 것을 벌점으로 내림).

## 지금까지 확정된 수치

### 컷편집 (숏폼 2편 실측 · S015·S016 수정본 기준)

```
IN  = max(말 시작, 직전 무음 끝)  − 0.08      OUT = min(말 끝, 직후 무음 시작) + 0.07
무음 ≥ 0.65초면 잘라낸다          (0.56 은 남겼고 0.76 은 잘랐다)
무음 문턱 −30dB · 컷 판단 0.30초+ · 경계 스냅 0.12초+
확신도 p < 0.30 낱말은 경계 계산에서 뺀다 (문구 비교에는 쓴다)
```
**성적 — 경계 50개 평균오차 0.051초(1.5프레임) · 최대 0.28초.**
S016 은 컷 13개 구조가 정확히 맞았고 26개 경계 중 17개는 손도 안 댔다.
편향·다른 규칙을 넣어 봐도 나아지지 않아 **그대로 둔다**.

### 자막 (같은 2편)

```
큐 14자 최대 · 큐 끝 쉼표·마침표는 뗀다 (되풀이면 남긴다)
금지(검사 반려) : 14자 초과 · 의존명사로 시작
선호(벌점 150) : 보조용언(않·싶) · 방위명사(안·위·상단…) 앞에서 안 끊는다
표기 통일      : '더원 트레이더' → '더원트레이더'
```
**성적 — 끊는 자리 35/53 · 문구 일치 71%.** 두 확정본이 검사를 통과한다.

### 상단 배너 (13편 · 대본 붙는 것 8편)

```
대본 제목을 두 도막으로 쪼개 앞뒤를 뒤집는다
   앞도막(주제) → 아랫줄 (7~11자)   뒷도막(약속·도발) → 윗줄 (8~14자)
   아랫줄 ≤ 윗줄 · 부호는 윗줄에 하나 (없어도 된다)
```
자세한 것은 `숏폼_프로젝트모음/상단배너_공식.md`.

## 도구

```bash
# 컷편집 (tools/cutedit — 두 시리즈 공용)
python tools/cutedit/transcribe.py  <작업폴더>            # STT
python tools/cutedit/silences.py    <작업폴더>            # 무음 두 벌
python tools/cutedit/align_take.py  <작업폴더> <대본.txt>  # 마지막 테이크 고르기
python tools/cutedit/verify_text.py <작업폴더>            # 갈린 문구만 large-v3 로 재확인
python tools/cutedit/cut_and_srt.py <작업폴더> --source <원본.mp4> --name <이름>
python tools/cutedit/make_xml.py    <작업폴더>/cuts.json <결과.xml>
python tools/cutedit/srt_rules.py   check <자막.srt>      # 납품 전 필수

# 롱폼 (L08 부터) — 캠 녹화와 PD 설명 녹화를 각각 STT·정렬·컷편집한 뒤 합친다
python tools/cutedit/docx_script.py <대본.docx> <대본.txt>
python tools/cutedit/align_take.py  <캠폴더> <대본.txt>
python tools/cutedit/align_take.py  <PD폴더> <대본.txt> --exclude <캠폴더>/aligned.json   # 캠 줄은 비운다
python tools/cutedit/cut_and_srt.py <폴더> --long --source <영상.mp4> --name <이름>   # 두 폴더 각각
python tools/cutedit/srt_rules.py   check --long <자막.srt>
python tools/cutedit/assemble_longform.py <캠폴더> <PD폴더> <대본.txt> --pd-src <PD에게 설명.mp4> \
        --motion <움직임.json> --name <이름> --out <결과폴더>      # 움직임 파일 없으면 만든다
python tools/cutedit/make_xml.py    <결과폴더>/assembled.json <전체.xml>

# 더원트레이더 전용
python tools/theone/srt_index.py   <자막폴더> --out 인덱스.md --json 인덱스.json
python tools/theone/srt_index.py   <자막폴더> --find 눌림목 역추세
python tools/theone/stills.py      sheet <최종본.mp4> <결과.png> 3 12 22 35
python tools/theone/pairs.py       <숏폼_프로젝트모음> --out pairs.jsonl
python tools/theone/banner_model.py pairs.jsonl --report | --near | --score | --propose | --chroma
```

환경 — `faster-whisper` `imageio-ffmpeg` (컷편집) · `torch(cpu)`
`sentence-transformers` `chromadb` (배너 분석. 모델 KURE-v1 은 처음 한 번 2.2GB).

## 롱폼으로 넘어갈 때

### 컷 경계 세 값은 **그대로 쓴다**

```
CUT_SIL 0.65초 · 무음 문턱 −30dB · IN/OUT 핸들 0.08 / 0.07
```

**이정찬 본인의 편집 로직이다** (2026-09-09 확인). 선배 취향이 아니라 이 사람이
컷을 자르는 방식이라서, 포맷이 바뀌어도 따라온다. 롱폼에 그대로 적용한다.
(앞서 이 셋을 "롱폼에서 다시 재야 한다"고 적었던 것은 내 착각이었다.)

### 자막 글자 수만 **롱폼 기준으로 다시**

**자막은 소리가 아니라 화면 폭이 정하기 때문이다.** 숏폼은 1080×1920 세로,
롱폼은 1920×1080 가로다. 같은 글자 크기라도 한 줄에 들어가는 수가 다르다.

**실측 (더원 롱폼 최종본 L04·L05 에서 자막 21개)**

| | 숏폼 | 롱폼 |
|---|---|---|
| 화면 | 1080×1920 | 1920×1080 |
| 큐 글자 수 | 3~**14**자 · 중앙값 8 | 10~**21**자 · 중앙값 15 |
| 자막 모양 | 검정 박스 + 흰 글씨 | 검정 외곽선 + 흰 글씨 (박스 없음) |
| 줄 수 | 한 줄 | 한 줄 |

롱폼 상한이 숏폼의 1.5배다(21/14). 화면 폭 비(1920/1080=1.78)보다는 작다.
※ 표본 21개에서 나온 **관측 최댓값**이지 확정 상한이 아니다. 롱폼 확정본
자막이 생기면 그걸로 다시 잰다.

→ `cut_and_srt.py --long` 이면 큐 **21자** · 시퀀스 1920×1080 · 10자 미만 조각 벌점이
붙는다 (아래 L08 표). 나머지 규칙(의존명사 금지 · 보조용언/방위명사 벌점 · 큐 끝 구두점)은 그대로.

### L08 에서 확인한 것 — 첫 롱폼 컷편집 (2026-09-11 · 더블 볼린저밴드)

**촬영이 두 번이고, 둘을 대본 순서로 섞어야 대본 전체가 된다.**

| 녹화 | 담긴 것 | 쓰는 법 |
|---|---|---|
| 캠 (`컷편집용.mp4`) | 대본 **형광 줄** — PD 가 「챕터 N 인트로 멘트」 식으로 끊어 딴다 | 얼굴 영상 + 소리 |
| PD 설명 (`PD에게 설명.mp4`) | 차트 화면 녹화. **일반 줄을 읽고**, 바로 이어서 그 내용을 차트로 **시연**한다 | 읽는 부분은 **소리만** · 읽기 끝 ~ 다음 읽기 전 = 그 부분의 **화면** |

첫 납품에서 PD 녹화를 캠 컷 위 V2 시각자료로만 얹었던 것은 구조를 잘못 안 것이다
(이정찬 정정 2026-09-11). 그때 만든 `pd_overlay.py` 는 지웠다.

| 대본 105줄 (docx → 문장 단위) | 줄 수 |
|---|---|
| 캠 녹화에서 찾음 | 50 |
| PD 설명 녹화 나레이션에서 찾음 | 50 |
| 어디에도 없음 — 챕터 제목 4 · 아웃트로 「더원 트레이더와 함께하는 실시간 라이브…」 1 | 5 |

결과 — 캠 27컷 278.20초 + PD 나레이션 22컷 304.55초 → **합본 49컷 582.82초 (9분 43초)** · 자막 233큐.
PD 녹음에서 뺀 것 — 대본에 없는 스퀴즈 정의 추가 멘트(1208~1224초) · 프리스타일 손절·익절 설명의
**소리**(화면은 시연으로 쓴다). 둘 다 이정찬 결정.

**나레이션 덩어리** — PD 나레이션 줄 사이 간격이 0~8.8초(재녹음·숨)와 36.5초 이상(시연) 두 무리뿐이라
20초에서 가른다. L08 은 9덩어리.

**시연 화면 — 연필 포인터가 움직이는 구간만** (이정찬 지시 — 어려우면 시연 전체를 V2)
- 포인터 프레임: 5fps 차분에서 작고(≤250화소) 뭉친(≤60화소) 변화. 작업표시줄·가격축만 바뀐 것은 뺀다.
  짚으며 설명하는 구간 76~88% · 나레이션 읽는 중 6%.
- 포인터 구간(2초 이상·밀도 0.5 이상)을 밀도 순으로 담아 나레이션 길이에 **딱** 맞춘다.
  넘친 만큼은 가장 긴 구간에서 깎는다 (마지막 구간을 깎았더니 0.67초짜리 조각이 생겼다).
- 80% 이상 차면 앞뒤로 한쪽 1초까지 넓혀 메운다. 그보다 모자라면 V1 은 시연 머리부터,
  **V2 에 시연 전체를 꺼 둔 클립**으로 둔다. 시연 전체는 나레이션보다 길어 다음 것과 겹치면 V3 으로 올린다.
- L08: 포인터 6덩어리 · 모자람 3덩어리 (21~26줄 68% · 44~46줄 0% · 71~73줄 0% — PD 와 대화만 한 구간).

**−30dB 는 이 녹음들에서 쉼을 거의 못 잡는다.** 방 소리 RMS −22~−30dB (잡음 바닥 캠 −34 · PD −30,
S015·S016 은 −45·−47). silencedetect 는 피크로 보므로 **문턱을 어디에 둬도** 안 된다. 쉼을 VAD 로
가져오는 것도 채점했는데 S015·S016 경계 평균오차가 0.051 → 0.101 로 나빠져 버렸다. 세 값은 그대로 두고
음량으로 재서 틀린 경계만 손봤다 — 캠 IN 4개(`cut_fix.json`) · PD 74줄 끝(`align_fix.json`, PD 목소리
「뭔가요?」가 붙었다). 말 뒤에 방 소리가 0.1~0.8초 더 붙은 OUT 은 말이 안 잘려서 그대로 뒀다.

**바꾸거나 새로 잰 것 — 전부 정답 자료에 대고 채점했다.**

| 무엇 | 결정 | 근거 |

| 약한 낱말도 VAD 가 말이면 경계에 | 버림 | S015·S016·L08 아무것도 안 바뀜 |
