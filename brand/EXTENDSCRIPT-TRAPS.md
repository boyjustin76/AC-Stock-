# ExtendScript·어도비 자동화 함정

포토샵(`tools/photoshop`) · 일러스트레이터(`tools/illustrator`) · AE·프리미어(`tools/ae`, `tools/premiere`)
가 **같은 언어(ExtendScript)와 같은 구조(COM/BridgeTalk + .jsx)** 를 쓴다.
한쪽이 밟은 함정을 다른 쪽이 다시 밟는 일이 반복돼서 한 곳에 모은다.

새로 밟으면 여기에 적는다. **증상 → 원인 → 처방** 순으로, 실측한 것만.

---

## 언어 자체

### ① 중첩 삼항을 쓰지 마라

```javascript
var v = a ? 0 : b ? 1 : 0.5;          // ✗
```

ExtendScript 는 이것을 `(a ? 0 : b) ? 1 : 0.5` 로 묶는다. 표준 자바스크립트와 결합 방향이 다르다.
`a` 가 참이면 `0` 이 되고, `0` 은 거짓이라 다시 `0.5` 로 간다.

**증상** — 조건에 맞는 가지를 안 탄다. 값을 찍어 보면 조건 변수는 분명히 맞는데 결과가 다르다.
2026-09-16 일러스트레이터에서 `align` 이 `"center"` 인데 `"right"` 가지를 탔다. 글자가 폭의
절반만큼 왼쪽으로 밀렸고, 원인을 bounds 갱신 지연으로 오해해 두 번 헛짚었다.

**처방** — `if/else` 로 푼다. 굳이 삼항을 쓰려면 괄호를 친다: `a ? 0 : (b ? 1 : 0.5)`.
현재 저장소의 삼항 6곳(`_ae.jsx:84,186` · `_types.jsx:216,309` · `c5b_ess_probe.jsx:23`)은
전부 괄호가 쳐져 있어 안전하다.

### ② `import` 는 없지만 `$.evalFile` 은 있다

같은 10줄을 파일마다 베끼면 그게 곧 SSOT 위반이다.

```javascript
$.evalFile(new File(new File($.fileName).parent.fsName + "/_lib.jsx"));
```

`tools/photoshop/_labdir.jsx` · `tools/illustrator/_lib.jsx` · `tools/premiere/_labdir.jsx` 가 이 방식이다.

### ③ JSON 이 없는 판이 있다

`eval("(" + txt + ")")` 로 읽는다. 파일은 `f.encoding = "UTF-8"` 을 **먼저** 지정하고 연다 —
빼면 한글이 깨진다.

### ④ 문자열 안에 진짜 줄바꿈이 들어가면 파싱이 깨진다

스크립트를 파이썬·셸로 생성할 때 `\n` `\r` 이 이스케이프가 아니라 실제 제어문자로 박히는 일이 있다.
`문자열 상수가 종결되지 않았습니다` 오류가 나면 이것부터 의심한다 (`cat -A` 로 `^M` 확인).

## 실행 환경

### ⑤ `$.getenv` 는 앱이 **켜진 시점**의 환경만 본다

앱이 이미 떠 있으면 그 뒤에 `set` 한 환경변수가 안 간다.

**증상** — 드라이버(PowerShell)에서 분명히 넣었는데 jsx 에서 빈 값이다. 앱을 껐다 켜면 된다.
2026-09-16 일러스트레이터에서 확인.

**처방** — 경로 같은 건 파일로 넘긴다. `tools/illustrator/run.ps1` 이 `_paths.json` 을 쓰고
`_lib.jsx` 의 `readPaths()` 가 읽는다. (환경변수를 **첫 후보**로만 쓰고 못 찾으면 폴더를 탐색하는
`tools/ae/labdir.*` 방식은 이 함정에 안 걸린다 — 안 가도 동작한다.)

### ⑥ 남이 쓰는 앱을 건드리지 마라

꺼진 앱을 켜는 건 무해하다. 위험한 건 **문서를 열어 둔 사람이 있는 앱**이다.

**증상** — 앱이 `응답 없음` 으로 멈춘다. CPU 를 재 보면 6초에 +0.8s 로 사실상 0 이고 메모리도 고정이다.
2026-09-16 사용자가 직접 쓰려고 띄워 둔 일러스트레이터에 빌드를 던져 9분 넘게 멈췄다.
그 잡은 24.7MB 원본을 열고 문서 사이로 항목을 복사하는 것이라 남의 문서와 엉킨다.

**처방** — `Get-Process` 로 프로세스만 보지 말고 **열린 문서 수**까지 본다.
`tools/illustrator/run.ps1` 이 `Documents.Count > 0` 이면 멈추고 `-Force` 를 요구한다.
프로세스 ID 가 전과 다르면 사람이 새로 띄운 것이다 — 그것도 단서다.

**멈췄을 때** — 강제 종료해도 대개 잃을 게 없다. 다만 **읽으려고 연 원본이 dirty 로 남아 있을 수 있으니
절대 저장하지 않는다** (⑩ 과 같은 이야기).

### ⑦ 프리미어가 켜져 있으면 BridgeTalk 잡이 프리미어의 AE 로 들어간다

AE 잡을 보냈는데 엉뚱한 인스턴스에서 돈다. 프리미어의 다이내믹 링크 매니저가 자기 AE 를 따로 띄우기
때문이다. 잡은 "성공"으로 끝나는데 팩 파일이 안 바뀌어 있으면 이것을 의심한다.

**처방** — AE 잡 전에 프리미어를 끈다. 한 번에 한 잡씩 돌리고 `c8q` 로 정상 종료한다.
`<작업실>/_target.txt` 에 `getSpecifier` 가 실측한 대상과 `getTargets` 전체 목록이 남으니 거기서 확인한다.

**같이 오는 함정** — BridgeTalk 응답이 유실되어 600초를 기다리는 일이 있다. 그때도 **잡은 이미 끝나 있다.**
완료 판정은 반환값이 아니라 `<작업실>/log/<잡>.txt` 의 `판정` 줄로 한다.

## 문서 다루기

### ⑧ 닫은 문서는 읽을 수 없다

```javascript
doc.close(SaveOptions.DONOTSAVECHANGES);
"OK " + doc.artboards.length;          // ✗ Error 45: 개체가 잘못되었습니다
```

**처방** — 닫기 전에 세어 둔다. 같은 실수를 `dump_ai.jsx` 와 `build_live.jsx` 에서 두 번 했다.

### ⑨ 만든 문서를 안 닫으면 쌓인다

빌드를 열한 번 돌렸더니 탭이 열한 개였다(2026-09-16 사용자 발견).
`saveAs` 로 디스크에 쓴 뒤 닫는다. 내용은 이미 파일에 있다.

### ⑨-2 CS6 호환(`ILLUSTRATOR17`)으로 저장하면 사람이 열 때마다 창이 뜬다

```javascript
so.compatibility = Compatibility.ILLUSTRATOR17;   // ✗ 글자가 '이전 버전 텍스트'가 된다
so.compatibility = Compatibility.ILLUSTRATOR24;   // ○ 현재 형식 (2026 판에서 고를 수 있는 최신값)
```

스크립트로 다시 열면 "이 파일에는 이전 버전 텍스트가 있습니다 — 업데이트하면 문자 위치가 바뀔 수 있다"
**모달 창이 떠서 스크립트가 거기서 멈춘다.** 사람이 열어도 같은 창이 뜨고, 확인을 누르면 글자가 움직일 수 있다.
팀장이 직접 고칠 파일이라 치명적이다 (2026-09-17 옻칠판 .ai 를 다시 열어 확인하다 걸림 — 라이브화면 .ai 도 같았다).

곁가지 둘
- 그 창이 떠 있는 동안 파일이 잡혀 있어서, 같은 파일에 다시 `saveAs` 하면 "읽기 전용이거나 사용 중" 으로 실패한다.
- 확인용으로 열 때 `UserInteractionLevel.DONTDISPLAYALERTS` 를 켜면 창이 안 떠서 **문제가 가려진다**
  (`legacyTextItems` 도 0 으로 나왔다). 사람이 겪을 창을 보려면 알림을 켠 채 열고 화면을 찍어 본다.

### ⑨-3 남의 원본을 열 때 끊긴 링크 창이 뜨면 스크립트가 멈춘다

트팩 원본 .ai 에 `09012023_15.jpg` 링크가 끊겨 있어 "연결된 파일을 찾을 수 없습니다 — 바꾸기/무시" 창이 떴고,
빌드가 그 창 앞에서 한없이 기다렸다 (2026-09-17 사용자가 화면에서 발견 — "빌드가 오래 걸린다"의 정체).

**처방** — 읽기만 할 원본은 여는 동안만 `UserInteractionLevel.DONTDISPLAYALERTS` 로 연다. 링크를 고치려고 원본을
저장하지 않는다. (반대로 ⑨-2 처럼 **사람이 겪을 창을 확인하려는** 열기에서는 알림을 켠다 — 목적에 따라 갈린다.)
창이 떠서 멈췄는지는 COM 이 답을 안 줄 때 화면을 찍어 보면 바로 안다. 이 창은 UI Automation 에 안 잡혀서
키 입력(한글 IME 가 켜져 있으면 씹힌다) 대신 좌표 클릭으로 닫았다. **더 나은 방법은 ⑨-5 다.**

### ⑨-4 `pdfCompatible = false` 로 저장하면 PDF 오류 창이 뜬다

시험 스크립트에서 `IllustratorSaveOptions.pdfCompatible` 을 `false` 로 두고 `saveAs` 했더니 모달이 떴다
(2026-09-21 실측, Illustrator 30.8.1):

> Acrobat PDF 파일 포맷에 문제가 있습니다. The size of the passed callbacks struct is wrong.

COM 이 그 앞에서 멈췄다 (CPU 20초 증분 0.41s = 사실상 0). **`pdfCompatible = true` 로 두면 안 뜬다** —
`build_live.jsx`·`build_rollad.jsx` 가 원래 그렇게 하고 있었는데, 시험을 짜면서 "PDF 는 필요 없으니"
꺼 버린 것이 원인이었다. 파일이 커지는 게 싫어도 끄지 마라.

### ⑨-5 모달 내용은 `PrintWindow` 로 떠서 읽는다 — 화면 캡처·UIA 보다 확실하다

⑨-3 에서 쓴 두 방법은 각각 구멍이 있다. 화면 캡처는 **다른 창에 가려 있으면** 안 찍히고(2026-09-21 실제로
겪었다 — 창은 `보임=True` 인데 화면에는 없었다), UI Automation 은 어도비 자작 그리기 창의 속을 못 읽는다
(`FindAll(Descendants)` 가 `OS_ViewContainer` 하나만 준다).

**처방** — 프로세스 id 로 최상위 창을 다 뒤져 클래스가 `#32770` 인 것을 찾고(그게 모달이다), 그 핸들에
`PrintWindow(h, hdc, 2)` 를 걸어 비트맵으로 뜬다. 가려져 있어도 나오고, 사용자 화면을 건드리지 않는다.
**모달인지 아닌지는 메인 창(`클래스=illustrator`)이 `IsWindowEnabled = False` 인지로 판별한다.**

닫을 때도 좌표 클릭보다 `PostMessage(dlg, WM_KEYDOWN/UP, VK_RETURN)` 이 낫다 — 포커스를 뺏지 않아서
사람이 다른 일을 하는 중에도 안전하다. 다만 **닫으려 애쓰기보다 죽이고 기록하는 편이 낫다**
(공용 실행기 제안, next_step 46).

### ⑩ mogrt 내보내기가 dirty 프로젝트를 디스크에 저장해 버린다

`exportAsMotionGraphicsTemplate()` 은 두 가지를 같이 저지른다.

1. **`true` 를 주고도 푸티지가 빠진 mogrt 를 쓴다.** 무작위로 난다. 반환값은 증거가 아니다.
2. **열려 있는 프로젝트를 디스크에 저장한다.** 시험 삼아 만진 상태였다면 그 상태가 그대로 박힌다.
   (가끔 메모리 안 프로젝트를 템플릿 컴포지션 하나로 줄여 놓기도 한다.)

**처방** — 팩 **밖** 폴더로 내보내고 → zip 을 풀어 `project.aegraphic` 안 푸티지를 검사하고 →
실패분만 다시 내보내고(`_only.txt`) → 전부 통과한 뒤에 팩으로 옮긴다. `tools/ae/trad_rr_export.ps1` 이 그 순서다.
읽기 목적이면 저장하지 않고 닫는다. 이미 더러워진 `.aep` 는 고치려 들지 말고 **소스에서 다시 짓는다**(`c5`).

### ⑪ 프리컴프에서 올라온 '필수 속성'은 스크립트로 다시 열 수 없다 (`canAdd=false`)

프리미어 이펙트 이야기가 아니라 **AE 필수 속성** 이야기다. 소스 컴포지션에서 연 컨트롤은 전체 컴포지션의
레이어에 `ADBE Layer Overrides` 로 올라오는데, 거기서 `addToMotionGraphicsTemplate` 을 부르면 거절당한다.

실측 (2026-09-14, `c5b_ess_probe`)

    크기 · 위치 · 색 · 문구   canAdd = false
    같은 레이어의 불투명도      canAdd = true      ← 프리컴프를 안 거친 속성이라 된다

UI 에서 손으로 끌어다 놓는 것은 되는 기능이다. 스크립트에서만 막힌다.
그리고 **컨트롤이 0개면 mogrt 내보내기가 `false` 를 준다** — 그래서 그냥 두면 안 된다.

**처방** — 프리컴프 속성을 열려고 애쓰지 말고, 전체 컴포지션에 **널을 하나 세워 그 위치·크기를 연다.**

    var all = comp.layers.addNull(comp.duration);
    all.name = "전체 조절";
    expose(comp, tr(all).property("ADBE Position"), "위치");
    expose(comp, tr(all).property("ADBE Scale"), "크기");

문구·색은 소스 mogrt 와 소스 aep 쪽에서 바꾼다. 소스가 전체를 표현식으로 읽게 만들면
**소스만 떼어 쓸 때 깨지므로** 하지 않는다.

## 좌표·측정

### ⑫ 텍스트 프레임의 `top`/`left` 는 글자가 실제로 차지하는 자리가 아니다

어센더·행간 몫이 들어 있다. 칸 안에 앉히려면 `geometricBounds` 를 재서 옮긴다.
`tools/illustrator/build_live.jsx` 의 `text()` 가 **놓고 → 다시 재서 → 남은 차이만큼 또 옮기는**
두 바퀴 방식이다. 글꼴이 바뀌어 상자가 달라져도 스스로 맞춘다.

### ⑬ 글자·크기를 바꾼 직후의 `geometricBounds` 는 갱신 전일 수 있다

`app.redraw()` 를 부른 뒤 잰다. (다만 ①의 증상과 헷갈리기 쉽다 — 먼저 ①을 의심하라.)

### ⑭ 일러스트레이터 캔버스는 원점에서 ±8172pt 다

아트보드를 가로로만 늘어놓으면 여섯 개째에서 `Error 1200 ... 'AOoC'` 가 난다.
행·열 격자로 배치한다 (`build_live.jsx` 의 `COLS`).

### ⑮ PNG 내보내기는 `transparency` 만으로는 부족하다 — `matte` 를 꺼야 한다

```javascript
eo.transparency = true;
eo.matte = false;          // 빼면 투명부를 matteColor(기본 흰색)로 채운다
```

**증상** — 100% 미리보기는 투명한데 큰 배율 내보내기만 불투명 100% 로 나온다.
2026-09-16 일러스트레이터 417% 내보내기에서 확인 (미리보기 22.7% vs 내보내기 100%).

### ⑯ 쓰기 직후 확인은 **거짓 실패**를 만든다

내보내기 계열(`saveFrameToPng` · `exportAsMotionGraphicsTemplate` · `exportFile`)은 호출이 돌아와도
파일이 바로 안 보인다. 직후에 `File.exists` 를 보면 "안 생겼다" 가 나온다.

**증상** — 로그는 실패인데 폴더를 열어 보면 파일이 다 있다.
2026-09-14 AE 에서 "0장 만들어졌다" 고 보고했는데 디스크엔 6장이 다 있었다. `$.sleep(200)` 은 모자라
크기를 절반으로 읽기도 했다.

**처방** — `$.sleep(600)` 뒤에 **File 을 다시 만들어** 확인한다. 같은 File 객체를 재사용하면
캐시된 상태를 본다. `a5_mogrt.jsx` 가 같은 이유로 `$.sleep(400)` 을 쓴다.

> **이 함정이 위험한 진짜 이유** — 거짓 실패를 보고 **엉뚱한 원인을 확정**하게 된다.
> `a3_frame2.jsx` 는 "`saveFrameToPng` 이 조용히 실패한다" 를 잡으려고 경로 표기법 6가지를 쟀고
> "⑥ 이미 열어 둔 File 만 된다" 로 결론 났다. 다섯 달 뒤 디스크를 보니 ①~④ 도 전부 같은 크기로
> 멀쩡히 있었다. ⑥ 만 통과한 것처럼 보인 이유는 `f.open("w"); f.close()` 로 **미리 만들어 둔
> 0바이트 파일이 그 시점에 이미 존재**했기 때문이다. 표기법 문제가 아니라 타이밍 문제였고,
> 틀린 규칙이 코드에 다섯 달 남아 있었다 (2026-09-16 정정, `b7ae887`).

진짜 규칙은 이것뿐이다 — **문자열 말고 File 객체를 준다**(⑤ 만 진짜 실패), **확장자는 함수가 안 붙여 준다**,
**알파는 그대로 보존된다**(`transparency`/`matte` 같은 인자 자체가 없다 — ⑮ 와 다르다).

### ⑰ 문서 사이로 복사한 래스터에 `.width`/`.height` 를 박으면 멈춘다

```javascript
var dup = it.duplicate(내레이어, ElementPlacement.PLACEATEND);
dup.width = w; dup.height = h;                      // ✗ 응답 없음으로 굳는다
dup.resize(w / dup.width * 100, h / dup.height * 100);   // ✓
```

**증상** — 일러스트레이터가 `응답 없음` 이 되고 CPU 가 20초에 +1s(사실상 0), 메모리 고정.
2026-09-16 두 번 연속 9분 넘게 굳었다.

**처방** — `resize()` 로 배율을 준다. 비율을 안 지키고 늘릴 때도 x·y 배율을 따로 주면 된다.

> **진단이 한 번 틀렸던 기록** — 처음엔 "사용자가 직접 쓰려고 띄워 둔 인스턴스에 잡을 던져서
> 엉켰다"(⑥)고 봤다. 그럴듯했고 실제로 그 상황이기도 했다. 그런데 앱을 끄고 **내가 띄운 깨끗한
> 인스턴스**에서 다시 돌렸더니 똑같이 굳었다. 그제야 원인이 새로 넣은 코드라는 게 드러났다.
> **그럴듯한 원인이 눈앞에 있으면 진짜 원인을 덮는다.** 조건을 바꿔 한 번 더 재는 것으로 갈렸다.

### ⑱ 포토샵 텍스트는 `size` 와 `impliedFontSize` 를 같이 들고 있다

레이어에 변형이 걸려 있으면 둘이 함께 있고, 어긋나면 포토샵은 `impliedFontSize` 를 믿고
`size` 를 되돌린다. **같은 배율로 둘 다** 써야 한다 (`tools/photoshop/build_thumb.jsx`).

### ⑲ 포토샵 RGB 디스크립터의 초록 채널 키는 `grain` 이다

`green` 이 아니다.

### ⑳ 참고용 PNG 를 줄여서 자르지 마라 — 원본 `.ai` 에서 항목째 복사한다

8000px JPG 압축본을 1920 으로 줄여 자르면 **압축 + 축소로 두 번 열화**된다.
원본 안에 같은 그림이 원해상도 래스터로 들어 있다.

```javascript
app.activeDocument = refDoc;
var dup = it.duplicate(내레이어, ElementPlacement.PLACEATEND);   // 문서 사이 복사
app.activeDocument = doc;
```

찾을 때는 이름 대신 **아트보드 안 좌표 + 크기**로 식별한다(원본 레이어가 이름 없는 그룹 덩어리다).
`tools/illustrator/dump_caps.jsx` 가 후보와 보드별 미리보기를 뽑아 준다.

### ㉑ 래스터를 벡터로 바꾸면 질감이 죽는다

낙관(도장)을 `imagetosvg` 로 돌렸더니 단색 한 덩어리가 됐다.
**인주 질감(노이즈 침식)이 낙관의 정체성**이라 벡터화하면 그게 사라진다.
필요한 치수로 **다시 그리는** 것이 답이다(확대가 아니라 재생성) — `tools/style/trad.py` 의 `seal()`.

### ㉒ 문서보다 코드가 최신이다

한지 색이 무드보드 `#F3ECDF` · 코드 `#ECE3D3` · 틀 전용 `#F3EEE3` 로 셋이었다.

## 적어 둘 만한 원칙

- 경로를 박지 마라. 스스로 찾게 한다 (`labdir.*` · `_labdir.jsx`).
- 문구·색·좌표 같은 값은 **한 곳**에 모은다 (`COPY` · `palette` · `Z`).
- 고친 뒤에는 **실측으로 확인**한다. 눈으로 보지 말고 픽셀을 재거나 로그를 찍는다.
- 치환은 따옴표 모양을 가정하지 마라. 친 뒤에 같은 패턴으로 다시 훑는다.
- **색만 보고 정체를 정하지 마라 — 모양을 봐라. 그리고 모양 조건도 믿지 마라.**
  한지 위에서는 밝기로 글자와 종이 섬유를 가려낼 수 없다
  (먹 85 · 인주 292 · 단청 황 299 · **섬유 419**). 임계를 어디 두든 섞인다.
  판별은 **덩어리 모양**으로 한다 — 글자는 세로로 이어지고 섬유는 점이다.
  같은 실수의 다른 얼굴이 '제목만 있는 판에서 글자 획을 현판으로 잡는 것' 이고,
  처방도 같다(폭 150px 이상 이어진 것만 판으로 인정).

  **다만 모양 조건은 참을 거짓으로 만들 수도 있다.** 세로 6px 조건은 섬유를 걸러내지만
  문장 끝이 `.` 이나 `·` 였다면 그것도 같이 걸러낸다. 2026-09-16 배너 건에서 두 파일이
  같은 3px·13px 로 나왔는데 **하나는 진짜 물림(`)` 획)이고 하나는 섬유였다** —
  숫자만 보고 한 덩어리로 묶었다가 둘 다 틀리게 기록할 뻔했다.
  가른 방법은 **임계 3가지 × 세로조건 2가지 교차 측정**이었다. 진짜는 여섯 조합에서 다 같은 값이
  나오고, 섬유는 세로조건을 걸면 사라진다.
  숫자가 애매하면 **원본 해상도로 잘라 눈으로 본다.** `tools/legacy/roll_ad_check.py`(09-17 격리)
- **실패를 봤으면 실패한 자리를 직접 확인해라.** "파일이 안 생겼다" 는 보고를 믿기 전에 그 폴더를
  열어 봐라. **도구가 없다고 말하는 것과 실제로 없는 것은 다르다.** 거짓 실패를 믿으면 엉뚱한
  원인을 확정하게 되고, 그 규칙이 코드에 오래 남는다 (⑯).
- **한 번 재고 원인을 정하지 마라.** 2026-09-16 하루에 같은 실수가 셋 나왔다 —
  한 조합만 재고 "섬유다", 한 조합만 재고 "붙었다", 한 시점만 재고 "표기법이 문제다".
  마지막 것은 다섯 달 동안 틀린 채로 있었다. **조건을 바꿔 가며 여러 번 재고, 값이 갈리면 그게 단서다.**
- **남이 실측한 것을 요약해서 옮겨 적지 마라.** 이 문서의 ⑦·⑩·⑪ 이 그렇게 시작했다.
  전해 들은 세 줄로 적었더니 ⑪ 은 대상(프리미어 이펙트 ← AE 필수 속성)도 처방(XML 편집 ← 널 레이어)도
  틀렸다. 실측한 쪽이 직접 쓰거나, 쓴 다음 실측한 쪽에게 고치게 한다.
  ㉒ 와 같은 뿌리다 — 값이든 글이든 사본은 조용히 어긋난다.

```bash
grep -rnoE "C:[/\\\\]{1,2}(cmgwork|pprolab|aelab)[^\"',) ]*" \
  --include=*.jsx --include=*.js --include=*.mjs --include=*.py --include=*.ps1 --include=*.json .
```
